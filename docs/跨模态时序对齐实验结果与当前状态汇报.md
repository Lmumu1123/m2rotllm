# 跨模态时序对齐实验结果与当前状态汇报

> 数据来源：本地 `anomaly_detection` 原始分析目录及其生成结果。原始传感器文件、绘图结果和训练日志均不提交到 Git；本报告只保留可复现所需的配置、结论和关键数值。
>
> 报告状态：2026-09-13 汇总版。仓库中的实现以 `cross_modal_alignment/` 和 `docs/REPRODUCTION_GUIDE.md` 为准。

## 1. 一页结论

当前最可靠的结论是：毫米波雷达目标距离单元的相位位移包络，与触觉传感器的低频/慢变化趋势存在稳定对应关系；在主实验中，直接按时间戳对齐、目标距离单元为 bin 13 时，2 s 平滑后的 X 方向相关系数约为 `0.756`，10 s 平滑后约为 `0.970`，最优滞后位于 `0 s` 附近。

这说明数据具备开展跨模态融合的基础，但目前还不能据此宣称两个传感器在高频细节上已经完成精确同步，也不能把 DTW 得分直接当成对齐质量。当前工作的性质更适合表述为：

- 慢时间尺度的跨模态趋势对齐已经得到较强的实验支持；
- 高频相位/载波细节仍然受噪声、传感器输出定义和时间锚点影响；
- 多组数据、不同转速和故障工况下的稳定性尚未完成验证；
- 需要继续统一时间基准、提高雷达信噪比，并建立带空值对照的评估协议。

此前“粗对齐 + DTW 将相关系数提升到 `0.644`”的结果不再作为有效结论。复核发现，当时同时存在雷达数据格式、采样时间尺度、触觉列选择和 DTW 过拟合问题。

## 2. 数据与代码现状

### 2.1 主实验数据

| 数据 | 规模/格式 | 当前用途 |
|---|---:|---|
| 雷达原始文件 | 259,584 chirps，86,528 loops，约 129.8 s | 提取目标距离单元的相位位移 |
| 触觉 `data_0.csv` | 6,420 行，约 153.5 s，约 41.7 Hz | 提供 X/Y/Z 位移及速度特征 |
| 触觉 `data_0.bin` | 帧周期约 25 ms | 核验设备时间戳和原始帧结构 |
| 其他记录组 | `14-18-30-583`、`14-19-26-478`、`09-41-34-481` 等 | 做跨记录组的频率、尺度和滞后诊断 |

雷达格式已经校正为：4 个 RX、每 chirp 512 个实数 ADC 采样、每 loop 3 个 chirps，loop 频率为 `666.67 Hz`。它不是原先假设的交错复数 I/Q 数据。

### 2.2 仓库中的复现入口

已将原始分析逻辑整理到 `cross_modal_alignment/`，主要入口如下：

| 入口 | 作用 |
|---|---|
| `rd_alignment_test.py` | 校正后的主分析：相位位移、直接时间对齐、平滑扫描、滞后扫描、DTW 空值对照 |
| `bin_alignment_test.py` | 触觉原始二进制帧和设备时钟诊断 |
| `fine_align.py` | 多组数据的粗/细对齐及局部漂移诊断 |
| `scale_lockin_test.py` | 不同尺度和锁相特征的相关性扫描 |
| `tests/run_tests.py` | 相关性、约束 DTW 和可选真实数据测试 |

脚本已经去除对个人绝对路径的依赖。新服务器只需通过命令行参数或 `.env` 配置数据目录；原始数据、模型权重、日志和生成结果保持在仓库外部。

## 3. 校正后的主实验结果

### 3.1 时间范围和锚点

- 触觉有效样本：`6,420` 行，设备时间跨度约 `153.5 s`；
- 雷达：`86,528` loops，按 `666.67 Hz` 计算约 `129.8 s`；
- 主实验雷达相对触觉的时间偏移：约 `+13.603 s`；
- 有效重叠样本：`5,346`；
- 目标距离单元：`bin 13`；
- 直接时间对齐的滞后扫描在 `0 s` 处达到峰值，附近 `-1/+1 s` 的相关性明显下降。

主实验中，雷达和触觉的时间锚点来自不同设备/文件记录，因此 `+13.603 s` 是当前记录的工程时间偏移，不等同于已经完成硬件级时钟标定。

### 3.2 直接对齐和平滑尺度

下表是主实验 `rd_alignment_test.py` 输出的雷达特征与触觉特征相关性。`rd_disp` 表示目标距离单元的相位位移特征；`crude`、`rd_mag` 和 `rd_dop` 仅作为对照。

| 平滑窗口 | X 位移 | Y 位移 | Z 位移 | X 速度 |
|---:|---:|---:|---:|---:|
| 0 s | 0.071 | -0.006 | 0.017 | 0.074 |
| 0.5 s | 0.533 | -0.001 | 0.259 | 0.542 |
| 2 s | 0.756 | 0.058 | 0.565 | 0.760 |
| 10 s | 0.970 | 0.229 | 0.925 | 0.972 |

在报告的慢时间尺度上，相关性大致呈 `X > Z >> Y`。这描述的是跨模态相关性，不能与触觉原始位移的幅度方差混为一谈：原始触觉流的标准差反而是 `Y=77.76`、`Z=13.88`、`X=5.10`，说明“原始波动最大”不等同于“与雷达最匹配”。

### 3.3 特征和方法对照

直接时间对齐的相关性如下：

| 雷达特征 | X 位移 | Y 位移 | Z 位移 | X 速度 |
|---|---:|---:|---:|---:|
| `crude` | -0.540 | 0.315 | -0.083 | -0.572 |
| `rd_mag` | -0.563 | 0.407 | -0.011 | -0.590 |
| `rd_disp` | 0.071 | -0.006 | 0.017 | 0.074 |
| `rd_dop` | -0.531 | 0.309 | -0.097 | -0.562 |

这里的原始尺度相关性较低，主要反映了两种设备的输出定义、采样率和高频噪声差异。`rd_disp` 在平滑后明显改善，因此当前主线应继续围绕相位位移及其稳健的包络/低频表示展开，而不是使用全 ADC 幅度代理作为最终物理量。

### 3.4 DTW 与空值对照

主实验的 DTW 得分为：

| 雷达特征 | DTW 相关得分 |
|---|---:|
| `crude` | -0.460 |
| `rd_mag` | -0.482 |
| `rd_disp` | 0.928 |
| `rd_dop` | -0.382 |

但是，对 `rd_disp` 做循环移位后，DTW 得分仍为：

| 循环移位样本数 | 0 | 500 | 1,000 | 2,000 | 3,000 | 4,000 |
|---:|---:|---:|---:|---:|---:|---:|
| DTW 得分 | 0.928 | 0.905 | 0.904 | 0.832 | 0.919 | 0.930 |

因此 `0.928` 不能单独证明真实同步；它说明 DTW 在这类平滑、强自相关序列上容易吸收时移和形变。后续报告 DTW 时必须同时给出固定时间轴基线、循环移位空值分布以及参数约束。

## 4. 原始二进制时间诊断

`bin_alignment_test.py` 对触觉原始二进制文件的检查结果为：

- 触觉帧数：`6,422`；
- 设备时间跨度：`153.494 s`；
- 中位帧周期：`25.0 ms`；
- 检测到 `1` 次时钟异常/间隔异常；
- 雷达 loop 数：`86,528`；
- 该脚本使用的雷达时间锚点：约 `+13.555 s`；
- 与主分析的 `+13.603 s` 相差约 `48 ms`，应统一发射时刻、接收时刻和帧起始位置的定义后再做最终标定。

该脚本的局部滞后跟踪结果标准差约 `4.776 s`、范围约 `16.56 s`。由于输入通道和局部匹配较弱，这一诊断本身不稳定，不能作为“存在 4.8 s 时钟漂移”的证据。当前更可信的判断来自主实验 `rd_disp` 的滞后剖面：在所选有效重叠区间内，峰值位于 `0 s` 附近。

## 5. 多记录组的细对齐诊断

对另外两组记录的结果显示，粗尺度趋势可以获得较高相关性，但细粒度对齐并不稳定：

| 记录组 | 重叠时长 | 粗尺度相关性（0.5 s / 1.0 s） | 细对齐相关性 | 局部漂移估计 | 锁相最佳尺度 |
|---|---:|---:|---:|---:|---:|
| `14-18-30-583` | 42.8 s | 0.942 / 0.982 | 0.139 | 2.834 ms/s | 1.00，r=0.865 |
| `14-19-26-478` | 76.1 s | 0.907 / 0.967 | 0.233 | -0.264 ms/s | 1.05，r=0.852 |

这里“粗尺度相关性高、细对齐相关性低”并不矛盾：前者比较的是低频包络/趋势，后者试图解释更快的载波或局部细节。当前数据还不足以支持亚毫秒级同步或稳定的物理尺度变换结论。第二组的最佳尺度落在扫描边界 `1.05`，应扩大扫描范围并使用更多受控记录复核，不能直接解释为雷达 loop 频率发生了真实变化。

## 6. 历史结果的更正说明

原始分析存在以下问题，已在仓库代码和算法文档中修正：

1. 将雷达实数 ADC 错当成交错复数 I/Q；
2. 将 loop 频率按约 3.2 kHz 处理，实际应为 `666.67 Hz`；
3. 将 2,000 loops 误认为约 153 s，实际约为 3 s；
4. 触觉 CSV 存在额外字段，早期脚本把列和时间列错位；
5. 使用弹性 DTW 的高分作为对齐有效性的主要依据，未充分报告空值对照。

因此，`_test_align_out/alignment_info.json` 中的 `coarse_lag_on_ds=-56` 和早期 `0.644` 结果只能作为历史基线，用于说明问题是如何被发现的；它们不应作为当前实验结论或论文主结果。

## 7. MBHM 配套测试状态

本仓库同时维护 MBHM 数据适配和 SFN 预训练入口。当前本地数据检查结果为：

- 元数据记录数：`135,516`；
- HDF5 `vibration` 形状：`(135516, 24000)`，类型 `float32`；
- 标签为 10 类，类别计数已在 MBHM 汇报文档中列出；
- 数据划分：训练/验证/测试约为 `70%/20%/10%`；
- `max-samples=100, epochs=0` 的加载器 smoke test 可运行，但 `test_acc=0` 是预期现象，不能当作模型性能；
- 完整训练日志中可直接核验到的末期验证记录约为 `val_acc=95.55%`、`val_loss=0.1403`，相邻训练记录中的 `train_acc` 约为 `95.71%`。

MBHM 的完整分类结果和模型初始化差异见 [轴承故障分类可行性汇报](轴承故障分类可行性汇报.md)。数据集、checkpoint 和日志仍然放在仓库外部，迁移服务器时需要重新配置路径。

## 8. 当前风险与下一步

### 当前风险

- 雷达原始文件没有与触觉设备共享的硬件绝对时间戳，文件名时钟只能提供工程锚点；
- 主实验和二进制诊断的时间锚点相差约 48 ms，帧/loop 起始定义尚未完全统一；
- 相位展开、目标 bin 选择和视线方向投影仍可能影响跨记录组的一致性；
- 单组主实验的高相关性不能替代多工况统计验证；
- DTW 对平滑序列的空值分数偏高，不能直接用于模型选择或对齐质量排名；
- 当前 `fine_align` 的细节相关性低，说明高频信息尚未达到可稳定利用的程度。

### 建议优先级

1. 统一雷达/触觉时间锚点定义，并保存每次实验的时钟、帧率、目标 bin 和重叠区间元数据；
2. 对雷达做多 chirp 相干积累、邻近 range-bin 稳健聚合和相位质量/SNR 筛选；
3. 在启动/停止、不同转速、不同载荷和故障工况下重复采集，报告均值、方差和空值对照；
4. 以固定时间轴和相位位移包络作为主评估，DTW 只作为受约束的辅助分析；
5. 在完成对齐可靠性验证后，再评估跨模态特征是否能提升故障分类或状态预测性能。

## 9. 复现命令

在新服务器上安装依赖并准备外部数据后，可运行：

```bash
# 代码级测试
python -m cross_modal_alignment.tests.run_tests

# 校正后的主实验
python -m cross_modal_alignment.rd_alignment_test \
  --radar_bin /path/to/20260807-153437-1786088077053250.bin \
  --tactile_csv /path/to/15-34-23-384/data_0.csv \
  --radar_start_clock 15:34:37 \
  --target_bin 13 \
  --out_dir ./runs/rd_alignment

# 原始触觉二进制时间诊断
python -m cross_modal_alignment.bin_alignment_test \
  --tactile_bin /path/to/15-34-23-384/data_0.bin \
  --radar_bin /path/to/20260807-153437-1786088077053250.bin \
  --radar_start_clock 15:34:37 \
  --out_dir ./runs/bin_alignment

# 多记录组补充诊断
export ALIGNMENT_DATA_DIR=/path/to/alignment_data
export ALIGNMENT_OUT_DIR=$PWD/runs/rd_diagnostics
python -m cross_modal_alignment.fine_align
python -m cross_modal_alignment.scale_lockin_test
```

典型输出包括：`rd_results.json`、`rd_series.npz`、`results.json`、`aligned_series.csv`、`lag_track.npy` 和诊断图。建议把这些结果存放在 `runs/` 或其他仓库外目录；原始数据和生成物默认不会被 Git 跟踪。
