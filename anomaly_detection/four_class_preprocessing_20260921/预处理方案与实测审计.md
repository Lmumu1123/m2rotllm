# 接触式与毫米波四分类：预处理方案与本批实测审计

日期：2026-09-21。原始数据为 `data接触式和非接触式同时采集` 中的 12 个 DAT、12 个 bin。原始文件、旧环境实验、旧接触式实验及其结论均未修改。本目录是新数据的独立处理版本。

## 1. 对“是否必须严格对齐”的回答

**你的判断有一部分是对的：最终任务是正常/内圈/外圈/滚动体四分类，不必先解决逐点时间同步。** 两路记录长度不同、加速度采集包之间有等待，都不妨碍分别切窗、训练分类器或做类别层面的迁移。

但需要区分三件事：

1. **频率坐标和输入尺寸统一。** BearLLM 用一秒振动片段、DCT、补齐/截断及能量归一化，使不同采样率的接触式数据具有一致的频率坐标与输入尺寸。这是输入接口统一。
2. **任务语义一致。** 雷达观测的是复数散射响应及其运动调制，接触式测量的是传感器安装点的加速度。带宽、传播路径、多径、相位、幅频响应都不同。即便都做成 24000 维，也不能据此认定原权重可直接解释雷达。九个振动数据集上的有效性并不自动涵盖雷达模态。
3. **知识迁移。** 可以用本地有效的接触式 encoder 作为教师，让独立雷达 encoder 学习四分类语义或教师隐藏空间。这一步可以使用同一稳态工况的窗口集合，而不是一一对应的瞬时波形。

BearLLM 的正常 reference 本来就不是要求与故障 query 同一时刻采到的波形。其 `[B,2,24000]` 中两个通道是 query 与正常 reference；不是加速度与雷达，也不是 XYZ 的两个轴。[论文方法 4.1](https://arxiv.org/html/2408.11281v2#S4.SS1)、[官方 FCN 接口](https://github.com/SIA-IDE/BearLLM/blob/main/models/FCN.py)、[官方数据配对接口](https://github.com/SIA-IDE/BearLLM/blob/main/functions/mbhm.py)。

**建议主路线：先做无精确同步的四分类；需要证明瞬态对应或逐窗口隐藏量蒸馏收益时，再增加时间对齐。** 如果录制期间转速、负载或状态在变化，不能把整条记录当成同分布集合；需要可靠稳态区间标注、采样包时间戳，或重新采集。文件名只有开始时间，不能给出每个采样包的实际时刻。

## 2. 本批数据实际得到什么

全量导出 **88 个接触式一秒窗口、614 个雷达两秒窗口**。四分类部分为 **58 / 412**；剩余 keep、bigNormal 共 30 / 202 个窗口单独保存，标签为 -1，未擅自合并进正常或故障。

按“接触式窗口 / 雷达窗口”列出四类：

- normal：13 / 109。
- inBroken：15 / 101。
- outBroken：18 / 100。
- roll：12 / 102。

这些是窗口数，不是独立轴承数或独立实验次数。每个目标类别目前只有两个文件，分别对应两种波特率；是否独立启停、是否同一轴承实体、转速/负载/安装是否一致尚未确认。**不能把 412 个雷达窗口随机分成训练/验证/测试，再报告为独立实验泛化。**

接触式新数据确实有完整包，不再适用旧三份正常记录“零完整包”的结论。但是高波特率文件有大量断裂：四类 115200 文件共得到 32 个完整包，460800 文件只有 26 个。尤其 roll-460800 有 41 个可见包首，只保留了 3 个完整包。解析器记录了断裂、残缺字符与计数异常，未猜测补字符。

完整包只意味着记录语法、序号和长度通过检查，不证明无位错误或模拟饱和。本批若干完整包出现重复的 ±1.998604 极值；单位和量程未确认，需核查设备配置，不能直接称为 ±2g 削顶，也不能靠归一化消除潜在失真。每个窗口已保存三轴极值和交流 RMS。

雷达原始文件约 9.76 GB（十进制），按当前格式和完整帧推算，每条名义时长 96.3–122.8 秒。全部有不完整帧尾，已记录并丢弃；剩余不足两秒的完整帧也不拼到其他记录。

**雷达输出当前是候选版本：距离门尚未由几何确认。** 沿用旧实验 2I/2Q、共轭方向与帧起点假设，在 0.15–2.0 m 中按最初三帧平均反射功率找峰。正常/内圈约 0.462 m、滚动体约 0.482 m，外圈约 0.884 m；keep 也约 0.884 m。若实际目标距离没有改变，这很可能涉及选择到不同反射体或多径。不能按“哪个距离分类最好”选门，更不能把这些差异直接解释成故障。

各雷达文件已处理窗口中，`|int16| >= 32760` 的比例约为 0.13%–0.76%。这是近满量程审计值，不是已经确认的模拟削顶率；需结合硬件量程和原始幅值分布判断。原始数据缺少 DCA 丢包日志和帧起点证据，现有解析无法证明未发生流中间丢字节。

`20260920-184058-normal-11520.bin` 的波特率拼写保留原样，仅在建立候选录制关联时将 11520 映射为 115200；没有改文件名。

## 3. 接触式预处理：直接保留 BearLLM 输入约定

### 3.1 数据完整性与窗口

- 按 ASCII `序号,x,y,z;` 解析；必须是有限数值和 1…4096 的连续计数。
- 仅接收完整的 4096 点包。异常处放弃该包，等待下一包的序号 1；文件首尾残片不用，包间不拼接。
- 每包取 `packet[48:4048]`，即中间 4000 点、恰好一秒。采样率固定 4000 Hz；115200/460800 只表示传输波特率。
- 保存包在文件中的字节起点、可见包序号、一秒窗口相对包首的 12 ms 偏移。绝对窗口时间留空，不按包号乘 1.024 秒，也不按串口字节数反推。

### 3.2 DCN 与三轴

对 x、y、z 分别去均值，做未正交归一化 DCT-II，将 4000 个系数在**频域末尾**补零至 24000，最后归一化为 RMS=0.01。输出每包 `[3,24000]`，系数 k 的名义频率是 `k/2 Hz`；前 4000 维有效，后 20000 维为未观测高频占位。

选择去均值是为了处理本传感器明显静态偏置，并遵循此前本地数据集接口审计；官方仓库 demo 的 `functions/dcn.py` 本身不去均值，不能把两种版本混称完全相同。已经测试常量偏置和整体正比例缩放不会改变本实现输出。教师分支不加 Hann、不取绝对值、不转 log、不计算三轴模长、不做逐窗 PCA。[官方 DCN 代码](https://github.com/SIA-IDE/BearLLM/blob/main/functions/dcn.py)。

三轴各配同轴、同工况、独立正常录制参考，组成 `[3,2,24000]`，三轴放 batch 维。工况至少包括电机/轴承型号、转速、负载、接触安装及轴向；不同文件名不等于独立 run。正常参考只来自训练部分或事先固定的校准库，不能从测试集选取、不能用 query 自身或另一个轴充当 reference。

每包另外保存原始一秒 `[4000,3]` 和 5–800 Hz 的逐轴功率谱作为诊断对照。该功率谱采用一秒 Hann 窗，0.5 Hz 是补零后的显示网格，真实频率分辨能力约 1 Hz。它**不是**给原 FCN 的 DCN。

### 3.3 encoder 输出

服务器脚本固定 `eval()` 和梯度，检查 BatchNorm buffer 不变，输出每个窗口的：三轴 `[3,128,47]` 特征图、`[3,128]` 隐藏量、其 L2 归一化副本，以及 `[3,10]` 原 logits。47 个位置来源于 DCT 频率轴的下采样，不是 47 个时间帧。

先保留三轴独立输出；固定轴或三轴概率平均可作首轮对照。128 维均值/拼接适配属于额外融合选择，不能默认保持原头语义。更换为本地四类头时，以真实四类标签训练；原十类严重度标签不能猜测。若汇总原头概率，须根据服务器 checkpoint 的标签定义核实映射，而不是仅按编号臆定。

## 4. 雷达预处理：保留物理时序，使用独立输入接口

### 4.1 原配置的时间与空间含义

配置为 4RX、256 ADC、192 chirp/100 ms；单 chirp 的 idle+ramp 为 420+80 μs=500 μs。因此帧内 2000 Hz，平均 1920 chirp/s，**不能当作均匀 1920 Hz**。每帧放在 200 个网格位置中，前 192 个被观测，最后 8 个缺失；最后 chirp 到下一帧首 chirp 起点间隔为 4.5 ms。

TX mask=7 不是 3 个顺序发射通道，本次仍为 4RX，不构造虚假的 12 虚拟天线。后面的 12 个空间单元来自 4RX×3 相邻 range bin；相邻补零 bin 相关，不是 12 个独立传感器。

在配置、流格式假设成立时，解码为复 IQ，去快时间 ADC 均值，加 Hann，512 点 range FFT。确认距离后，用统一的物理 ROI（距目标 ±0.16 m）选峰，再固定该录制的中心与相邻三个 bin。窗口内不按故障标签选峰、不随分类结果改门、不自动切换 RX。

### 4.2 与已有环境处理相比，保留和调整什么

保留多空间单元、幅值尺度归一化、帧内 IQ 复均值移除，以及不跨缺口计算相位差。归一化与减均值是减少静态背景影响的候选手段，**不是已经证明消除了环境干扰**：幅值信息可能也是故障证据，逐帧减均值会抑制低频/改变谱形。因此同时保存原始单元功率作幅值对照，并保留未做跨频率形状归一化的谱。

调整重点是：

- 主谱分支改用完整帧内 Hann 谱、跨帧平均功率、跨单元中位数，避免主结论依赖未验证的跨帧绝对相位连续。
- 旧两秒 mask 最小二乘谱继续保存，但定位为有条件的相干谱消融；mask 不等于已经修复相位跳变。
- 不加载旧“三转速分类器”或其 scaler 来代替故障 encoder；本批没有匹配 off 记录，不套用其他几何的 off 标定。
- 保留 5–800 Hz 未池化的 1591 点谱输入。旧环境脚本在高频使用 20 Hz 分箱，可能合并故障谐波；本版不预先这样压缩。0.5 Hz 仅是统一网格，帧内谱真实分辨能力约为 `2000/192=10.42 Hz`，不能据此宣称分辨了相邻 0.5 Hz 的故障峰。
- 不盲目 notch 10 Hz 及其倍频。它们既可能是帧周期伪影，也可能与旋转/故障信息重叠，需配置或停机对照。

### 4.3 两种可供服务器使用的输入

**第一优先级：谱分支。** 每个不重叠两秒窗口输出 `frame_log_shape[1591]`，即 log10 帧平均功率减去频带均值。并保存 `frame_log_power` 和 `coherent_log_shape` 作消融。训练集统计的标准化参数在验证/测试时固定；不在完整数据上拟合 scaler。

**第二优先级：帧内时域分支。** 保存 `iq_frames[N,20,192,12,2]`，最后一维 I/Q；`phase_rate_frames[N,20,191,12]` 是相邻有效 chirp 相位差乘 2000，单位 rad/s，不能直接称为校准加速度。伴随有效 mask 和真实局部采样时间。服务器 loader 可变换为 `[N,20,12,2,192]`，逐帧卷积并 masked pooling，再汇聚 20 帧。不要将 20×192 直接拉平为连续 3840 点。

雷达 encoder 先训练 `1591→隐藏层→128→四类` 或带 mask 的帧内网络。**这里没有现成且已验证的雷达 BearLLM encoder 权重。** 本目录提供输入与读取接口，不把随机初始化的学生伪装为可用的预训练模型。若你服务器已有雷达 encoder，按其明确的输入约定选这个谱分支或 IQ 分支；不同架构需要实际适配。

不推荐把 log PSD 补零成 24000 维冒充 DCN，也不推荐积分/微分或任意重采样后默认与加速度同分布。雷达径向位移、速度与加速度之间的频率加权关系受散射机制、安装和噪声影响，数值可转换不等于教师特征可直接复用。

## 5. 不严格同步时，如何利用接触式模型

推荐按下面顺序推进，避免在预处理阶段强行规定同样的窗口数和时长。

1. **先核查教师。** 用本地标签评价冻结接触式 FCN，再比较仅训练四类头、解冻最后卷积块的适配。此前 426 条 MBHM 探索性子集的带宽消融，重训 FCN macro-F1 从 94.9% 降至低于 2 kHz 的 49.8%；这是旧报告结果，不是本批四分类性能。它说明“补零即可复用”缺乏保障，也不代表 4 kHz 硬件的性能上限。见 [旧接触式报告](../contact_validation_20260919/接触式预处理与embedding验证报告.md)。
2. **雷达监督基线。** 冻结输入处理，用真实标签训练简单线性/MLP 分类器，再训练雷达 encoder。必须保留主频、总体能量、单独转速/距离元数据对照，检查故障类别是否被实验条件替代。距离峰不能作为模型特征；即便不输入距离，选中不同反射体仍可能带入混淆。
3. **同录制集合级蒸馏。** 一组包含同稳态工况下的所有合格接触式一秒窗、所有合格雷达两秒窗。不按序号配对，不要求数目相等。教师侧汇聚隐藏量或四类概率，雷达侧独立采样若干窗口，匹配集合均值/分布；按录制平衡采样，避免雷达窗口更多的 run 占据更大权重。
4. **先用真实标签 CE，再加 KD。** 起点为四类 CE + 教师集合概率的 KL 蒸馏；教师在开发集确认有效后，再加隐藏均值的 cosine/Huber 项。教师冻结包括 BN。特征尺度只在训练集估计；不要强迫雷达复制接触式中它根本观测不到的瞬时高频信息。
5. **检验迁移是否有额外价值。** 比较同一个雷达模型的 CE-only、CE+logit KD、CE+logit+集合特征 KD，以及只用类别原型、同 run 内打乱、跨故障错误配对。若打乱时间不影响诊断，时间同步不应成为主贡献；若集合级迁移优于同模型监督基线，再讨论复用收益。

如果目标是“复用固定接触式诊断头”，先把接触式教师适配好并冻结，雷达学生学习输出到这一确定的 128 维坐标系，再接**同一套教师的头**。如果同时重训雷达头，应报告为新的四分类器。只替换为四类头不会自动兼容原十类语言适配器；本阶段先完成 encoder 与分类，LLM 接回去是后续需要验证的接口工作。

精确同步只有在研究瞬态事件、逐窗瞬时特征重建、时域波形回归等任务中才成为必要条件。本批包间等待无逐包采样时间，不能通过互相关或 DTW 强制获得“真实同步”；稳定周期振动尤其容易出现多个等价偏移。

## 6. 划分与下一步采集

两路对应录制、同一轴承实体、同一连续实验拆出的文件应分到同一组，再按组划分。只有两个文件/类，不能形成可信的独立 train/val/test 三份。可以先做两个录制组互换的开发诊断，但它同时混入波特率/保存质量变化，且独立性仍待确认；不能当论文最终结果。

正常参考库应额外采集并固定。若只有一条训练正常记录，它无法为自身提供独立正常 reference；服务器脚本会报告该正常查询缺参考，不用自身凑成成功输入。也可以研究不使用 reference 的新模型，但那已改变原 FCN 设定。

下一批优先保持同转速、同负载、同雷达距离与安装，四类各做独立启动重复，修复 460800 保存断裂，另采独立正常参考。若要论文级泛化，还需要多轴承实体留出。此处不要求为了采集配对，把接触式与雷达机械地设置成同样周期。

待确认的具体信息：keep 与 bigNormal 含义；四类是否同型号/同转速/同负载/同安装；雷达目标距离与是否换位置；各文件是否独立启停；接触式量程和滤波配置。确认距离后应重新导出雷达，输出到新目录，不覆盖当前候选版。
