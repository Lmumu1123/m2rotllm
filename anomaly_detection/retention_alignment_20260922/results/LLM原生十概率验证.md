# 原生十类概率进入实际 BearLLM/Qwen 的验证

日期：2026-09-22。此处已运行真实模型生成，不是用概率最大项拼接一段模板来冒充 LLM。

## 本轮接口和前轮区别

本轮使用接触/雷达共享分类头产生的真实十类概率 `p10_0…p10_9`，直接经过原 BearLLM 已训练的 `linear3`（包含其实际 LoRA 更新），输出 `5×1536` 振动 token，送入冻结 **Qwen2.5-1.5B-Instruct** 及原已训练 LoRA。全程不更新 LLM，也不把四类概率重新均分成三个严重度。

型号按本次实际资产核实：下载脚本与资产清单均指向 `Qwen/Qwen2.5-1.5B-Instruct`，revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`；生成时记录的模型 SHA-256 与该资产清单一致。`config.json` 的 `model_type=qwen2` 是模型实现家族名称，不能据此将实际版本误写成 Qwen2；原论文所述版本与本次开源资产版本须区分。

固定提示只要求输出 Normal、Inner race fault、Outer race fault 或 Rolling element fault 之一，不要求严重度。十类分布仍是模型内部状态，当前本地数据没有严重度真值，所以不声称验证了严重度识别。

真实标签未进入提示、振动 embedding 或 guard；只用于推理后的计分。原语义投影 live LoRA 与独立合并公式已数值核验，实际权重文件在生成前后哈希一致。

## 实测结果

| 实验 | 条数 | 结果 |
|---|---:|---|
| 原生十类 one-hot 控制 | 4 | 四种部位生成均正确，4/4 忠实于输入概率类别 |
| Stage A/B 主批次 | 144 | 131/144 原始 LLM 输出与概率类别一致，13 次冲突 |
| 保守共享头追加批次 | 8 | 8/8 原始 LLM 输出与概率类别一致 |
| 合计诊断批次 | 152 | 139/152 忠实，91.45%；0 解析失败，0 截断 |

152 是不同方法、处理、折和外部案例的输出行数，**不是 152 次独立物理录制**。主已知类别仍只有 8 份录制。52 行输入具有真实距离门不匹配标记，对应的可用诊断被规则层标记无效；原始 LLM 输出仍保留以供审查。

在两种预处理和两个录制留出方向合并的主样本上，每种方法有 16 行生成结果（8 份录制重复于两种处理）：

| 阶段 / 方法 | 原始 LLM 正确 | 与概率分类头一致 |
|---|---:|---:|
| A：未适配原头，embedding_only | 4/16 | 12/16 |
| A：未适配原头，ce_only | 16/16 | 16/16 |
| A：未适配原头，CE+特征对齐 | 14/16 | 14/16 |
| B：回放约束共享头，embedding_only | 13/16 | 13/16 |
| B：回放约束共享头，ce_only | 16/16 | 16/16 |
| B：回放约束共享头，CE+特征+KD | 16/16 | 16/16 |

这些是当前数据的探索/录制留出结果；外圈的雷达距离门问题尚在，不能把 16/16 直接当作四类故障机理已验证或论文级跨域泛化成功。B 的主批次使用 v1 留出头；新保守 all_known 头仅用于另外 8 行外部案例，不把训练拟合当作留出成绩。

## 原始 LLM 冲突必须保留

例如 Stage A、v0、115200→460800 的正常录制，概率头四类分布为 `[0.5882, 0.0188, 0.3439, 0.0490]`，最大项是正常，但原始语言生成却为 `Inner race fault`。相反方向也有同类错误。这说明仅有一个看似正确的分类概率，不能保证通过混合语义 embedding 后的语言一定忠实。

四个 one-hot 控制全部成功，也不能推出任意混合概率都成功。必须分别报告分类头诊断精度、原始 LLM 诊断精度和两者的一致率。

规则 guard 的处理独立保存：可用几何下，当原始语言无法解析或与概率最大部位冲突时，结构化结果采用分类头部位并标记冲突；几何不匹配则标记不可诊断。这个规则不读取真值，也不是学习得到的精度提升。不能把 guard 后的一致性 100% 写成“LLM 准确率 100%”。全部原始生成文字均保留在 CSV/JSONL。

## 泛化仍未解决

保守共享头的 v0 与 no_demean 版本共 4 条 bigNormal 结果全部预测外圈，原始 LLM 也输出外圈。因此语言层忠实执行了上游错误，本次没有恢复跨电机健康泛化。keep 输入距离门无效，且属于已知四类之外，不能用其被判成外圈来声称已完成未知故障检测。

RAG 可以为已确认的分类解释提供文献支持，但不能修正上游缺失频带、错误距离门或错误 embedding 这一类测量/模型问题。当前可采用明确的结构化分类输出和原始语言忠实度校验；若要训练语言层进一步提高混合概率下的一致性，必须同时回放旧语言任务，并重新验证原模型能力。

## 复现与文件

```bash
conda run --no-capture-output -n m2vllm python scripts/run_p10_llm.py \
  --inputs radar/llm_original_p10_inputs_plus_conservative.csv \
  --output /path/to/new_llm_output --device cuda:0
```
