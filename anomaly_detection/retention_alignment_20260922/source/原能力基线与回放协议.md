# 原能力基线与回放协议

本报告在 `m2vllm` 中实际执行，使用上一轮相同的、独立预训练的 BearLLM FCN；不修改原仓库、原 MBHM 数据和原权重。这里量化的是振动分类网络的回归性能，不是语言模型生成准确率。新模型的验收应与这里的同口径基线比较，原有准确率最多下降 **0.5 个百分点**。

## 1. 可直接使用的结果

主口径是：每个 query 使用原协议固定的三个健康参考，各自计算 softmax，再对三个概率向量取平均。一个 query 计一个样本。

| 划分 | 独立 query 数 | 原十类 Acc | 原十类 macro-F1 | 只合并成四类的 Acc | 四类 macro-F1 |
|---|---:|---:|---:|---:|---:|
| 原 validation 全量 | 24,558 | 98.9291% | 0.96678 | 99.1042% | 0.98732 |
| 原 test 全量 | 12,279 | 98.8680% | 0.91406 | 99.0553% | 0.98727 |

表中的“独立 query”只表示不把同一 query 的三次参考评估重复计数，**不表示独立轴承、独立电机或独立采集实验**。原划分不能支持这样的解释。

原训练脚本按 query-reference pair 计数。我们也完整复算了这个口径：test 36,837 对、十类 Acc **98.6725303363%**，与原 `pretrain/results.json` 中 `source_selected_checkpoint_test` 精确相同；validation pair Acc **98.6996769552%** 也与原训练保存值一致。这证明加载了正确的原 FCN，且没有把最终 LLM 的 adapter 误当成独立 FCN。

四类 Acc 在合并后略升是因为同一故障位置下不同严重程度之间的误判不再算错，不是训练提升。macro-F1 对各类别一视同仁，而 Acc 按样本数加权；原十类 test 中轻微滚动体故障只有 3 个 query，小类错误会明显影响 macro-F1。

## 2. 十类改四类的无训练基线

固定四类次序为 `normal / inner / outer / ball`。对原概率向量进行如下求和：

\[
p_4=[p_0,\ p_1+p_2+p_3,\ p_7+p_8+p_9,\ p_4+p_5+p_6].
\]

这是一层确定的概率聚合，无需重训 encoder 或十类头，原十类输出同时保留。不能直接对不同严重度的 logits 求和；应先 softmax 后求和，或者对每组 logits 做 logsumexp。不能把 argmax 十类标签映射后的结果与四类概率求和后的 argmax 混为同一个指标。

主基线仍然先按参考求 softmax，再平均。如果把三参考 hidden 先平均再过分类头，得到的是 `softmax(mean logits)`，通常不等于 `mean softmax(logits)`。我们分别保存和评估了两者：原 test 四类 Acc 前者为 **99.0309%**、后者为 **99.0553%**。新训练头要维持主评估口径，应对 `hidden_refs[N,3,128]` 逐参考运行，再平均概率。

## 3. 真实划分与参考限制

原 MBHM 元数据 135,516 行。只有同 condition 存在健康参考的 122,792 个 query 被原程序纳入；12,724 个 query 被排除，其中 CWRU 3,862、DIRG 6,120、MFPT 42、NCEPU 2,700。不能把本次高分解释为对所有原数据源故障均验证成功；部分来源在可评估子集中主要或仅有健康类。

已将原 `pretrain/dataset.json` 与 `evaluate_mbhm.make_protocol(seed=42,references=3)` 逐对完全比对，三种划分都一致：

| 原划分 | query 数 | query-reference 对数 |
|---|---:|---:|
| train | 85,955 | 257,865 |
| val | 24,558 | 73,674 |
| test | 12,279 | 36,837 |

原算法按符合条件的 query 的文件顺序，以序号模 10 划分为 7/2/1。每个 query 从同 condition 的全部健康行中有放回随机选三个参考，不限定健康参考属于 train；健康 query 也可能抽到自己。

具体审计结果：

- 原 train 的 257,865 对中，51,647 个参考来自 val 查询，25,789 个来自 test 查询，合计 **77,436** 个跨查询划分参考。
- 原 train/val/test 分别有 549 / 166 / 78 对以 query 自己作为参考。
- test 的 **257/257 个 condition** 在 train 中都出现。
- 元数据未提供足以构造独立轴承、原始长录制或独立电机划分的标识。

保留该协议是为了公平判断“相对现有模型是否退化”。它不是独立实体泛化测评，也不是无跨集合参考共享的严格评估。将参考池改成 train-only 是值得补做的新实验，但不能偷偷更换原回归基线后仍称同协议。

## 4. 回放缓存与使用边界

为避免把巨大原训练集重复编码，只从 **train query** 选回放样本：每个原十类最多 128 个，按可用 source 轮流分配名额；各 source 内用固定随机种子 `20260922` 打乱。选择发生在任何预测之前，不按对错筛选。除轻微滚动体只有 22 个 train query 外，其余九类各取 128，共 **1,174** 个。validation 和 test 均保留全量。

缓存总计 **38,011 query、114,033 query-reference 对**。三个参考与原训练划分缓存保持完全相同。这意味着回放只从 train 中选择了 query，但仍继承原协议的跨集合健康参考共享；不能声称回放接触的原始信号完全不含 val/test。

`cache.npz` 的各数组以相同第一维索引对齐：

| 数组 | 形状 / 含义 |
|---|---|
| `hidden_refs` | `[38011,3,128]`，ReLU(linear1(encoder))，逐参考原始特征 |
| `hidden_mean` | `[38011,128]`，三个参考 hidden 均值 |
| `logits10_refs` / `logits10_mean` | 原十类 logits，逐参考 / 均值 |
| `probs10_refs` / `probs10_mean` | 原十类 softmax，逐参考 / 均值 |
| `probs4_mean` | 原十类概率按故障位置聚合后的四类概率 |
| `label10` / `label4` | 原十类与固定映射后的四类真值 |
| `split` | `train`、`val`、`test`；禁止 test 用于调参或阈值选择 |
| `query_id` / `condition_id` / `source` | 原元数据标识 |
| `reference_ids` | `[38011,3]`，可追溯每个参考 ID |

`metadata.csv` 另提供 `cache_row`、参考 ID 和标签。`original_head.npz` 保存原 `linear2` 的 `weight10`、`bias10`。`baseline_metrics.csv` 含全局及逐 source 的十类、四类、query 与 pair 口径；完整混淆矩阵在 `baseline_metrics_detail.json`。

## 5. 旧能力保留的验收规则

应保存完全不变的原模型分支及其原十类输出，新增四类输出首先采用上述无训练聚合。若训练新的共享四类头，应采用旧 train 回放 + 本地 train 接触式样本，并在 validation 上选择满足约束的候选。test 仅在候选冻结后最终验收，不因看见 test 结果而反复改参。

同主口径下，0.5 个百分点阈值对应：

- 原 val 四类 Acc 99.1042%，候选至少 **98.6042%**。
- 原 test 四类 Acc 99.0553%，冻结候选最终至少 **98.5553%**。
- 若共享改动也影响十类输出，还需验十类：val 至少 **98.4291%**，test 至少 **98.3680%**。

这只是全局 Acc 下限，还应逐 source、逐故障类检查是否由“大类不变、小类崩溃”掩盖退化，并同时报告 macro-F1。阈值通过不等于证明对任意未来分布都无退化。原模型权重与路径完全保留，则原分支的同输入输出可做到严格不变；新的共享四类分支仍需要上面的数值回归验收。

不要把以前仅用 58 个本地窗口训练的新四类头当作原能力无损的证据。它从未经过此次旧源全量回归约束；当前源码/缓存使这一原则首次可测、可约束。

## 6. 带宽敏感性：补零并不能创造缺失信息

为了检验“相同 DCN 长度是否就意味着不同带宽无损泛化”，在原 **validation** 中提前固定了每个 source × 十类单元最多 8 个 query，共 **261** 个。没有使用 test 或本地分类结果来挑选样本。三参考均与主缓存一致。

MBHM 输入已经是 DCN，实验没有再次做 DCT，也没有先去均值。按照原一秒窗口约定，DCT-II 第 k 个系数对应约 k/2 Hz；把 4,000 或 1,600 及后面的系数置零，分别模拟只保留至约 2 kHz 或 800 Hz 的谱支持。查询与参考同时限带。`renorm` 重新按原 DCN 的 RMS=0.01 归一化，`no_renorm` 保留截断后的能量下降。

| 固定 validation 子集处理 | 十类 Acc | 十类 macro-F1 | 四类 Acc | 四类 macro-F1 |
|---|---:|---:|---:|---:|
| 原完整 DCN，不改变输入 | 93.4866% | 0.92748 | 96.5517% | 0.96348 |
| 至约 2 kHz，并重新归一化 | 59.0038% | 0.49075 | 72.4138% | 0.72747 |
| 至约 800 Hz，并重新归一化 | 32.1839% | 0.19850 | 40.2299% | 0.38653 |
| 至约 2 kHz，不重新归一化 | 58.2375% | 0.45847 | 75.4789% | 0.75574 |

这不是本地传感器的性能预测，也不是模拟了完整硬件抗混叠与机械传递函数；它是对同一源验证样本的受控频谱删除实验。它直接说明：**网络的谱坐标对齐与真实信息量充分是两件事。** 将 4 kHz 的一秒信号经 DCT 后补成 24,000 长度，不会恢复 2 kHz 以上已经采不到的谐振/冲击信息。雷达现有有效公共带宽更窄，也不能仅靠对齐损失假定所有故障信息仍可恢复。

这支持同时审查预处理、参考条件和观测带宽；不能仅凭本地 25% 就认定“预处理一定没有问题、只需换头”。另一方面，该实验也不能单独证明本地失败仅由带宽造成。本地 DC 去除、轴选择、异工况健康参考和测点传递路径需由其它配套消融分别诊断。

原 DCN 保留了第 0 个系数，本实验没有额外去均值。若本地处理曾去均值，那属于另一个需要明确记录和独立验证的域差异。
