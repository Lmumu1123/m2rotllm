# 接触式 BearLLM 教师验证与接口

原始 BearLLM 分类器目前不能直接诊断这一批电机外壳测点的数据。完成训练的独立 FCN 和最终 LoRA 适配器都把主实验的 8 个文件判成外圈故障；这支持在冻结表示上用训练录制拟合新的四类分类头，不支持直接蒸馏原分类器的错误标签。

这里实际执行了原权重推理，不是仅检查模型能否加载。原始文件、已有 BearLLM 权重及 `.env` 均未修改。运行环境为 `conda m2vllm`，PyTorch 推理使用 GPU 0；训练模式始终关闭，BatchNorm 缓冲区前后完全一致。

## 数据与参考协议

- 主四类：8 个文件、58 个完整 1 秒窗口，normal 13、inner 15、outer 18、ball 12。每个窗口 XYZ 三个视角，不把三轴算成三个独立实验。
- 附加导出：keep 18 窗、bigNormal 12 窗。保持原 `label=-1`，分别表示未知类型的底座故障、另一正常电机；均不进入四类训练或这里的主结果。
- 用户已确认采样率为 4000 Hz，两模态同步启动采集；各包缺少可靠绝对采样时刻，因此同时采集尚不等于窗口已严格对齐。
- 固定外部参考：从 MBHM 按源码划分的训练查询中，每个数据源选 1 条健康记录，共 9 条。NumPy `default_rng(42)`，先选参考，再做本地推理。ID 和来源见 [external_reference_protocol.json](external_reference_protocol.json)。
- 所有查询都使用同一组外部参考，分别推理后平均概率和隐藏表示，再平均 XYZ。没有用本地 normal 测试文件作为参考，也没有按测试成绩挑选参考。
- **外部参考并非该试验台同工况参考，这属于跨工况诊断，不能称为 BearLLM 原论文同工况协议的严格复现。** Zero-reference 仅为敏感性对照，同样不是训练时的原协议。

## 权重来源和预处理兼容性

| 模型 | 实际来源 | 完成状态 |
|---|---|---|
| retrained_fcn | `/media/nas_users/huangyating/bearllm-runs/released-code-seed42/pretrain/fcn` | 完整预训练流程，19 轮早停，按已有验证规则选择第 11 轮 |
| retrained_final | 同实验目录 `finetune/weights` | 50 轮微调完成；包含该权重对应的 LoRA 更新 |
| official_final | `/media/nas_users/huangyating/bearllm-assets/bearllm_weights` | 已下载的官方最终适配器及对应 LoRA |

本批数据每个完整包 4096 点，原预处理取中间 4000 点，对每轴去均值，然后计算**有符号 DCT-II 系数**，在系数域补零至 24000，按全部 24000 维归一化到 RMS 0.01。检查结果与已有导出一致。去均值是针对本地加速度静态分量的明确调整；没有把谱幅值误作原 DCN 输入。

1 秒窗口中 DCT 第 k 个系数对应约 k/2 Hz，因此 4000 Hz 采样只有 0–2 kHz 的测量支持；其余 20000 个系数补零只是接口适配，无法恢复原传感器不存在的高频信息。`[batch, 2, 24000]` 的两个通道分别为查询与正常参考，不是两个加速度轴。冻结 encoder 输出 `[batch,128,47]`，分类头第一层 ReLU 后为 128 维。

最终适配器的 `linear1/linear2` 必须加上**同一目录** LoRA 权重，不能随意拿独立 FCN 分类头替代。独立核验了本脚本合并后的推理与仓库原 PEFT 加载器的一致性：新训练最终权重最大 logit 差 `3.8e-6`，官方权重 `2.9e-6`。证据见 [adapter_equivalence.json](adapter_equivalence.json)。

四类概率从原十类概率求和：

```text
normal = p10[0]
inner  = p10[1] + p10[2] + p10[3]
outer  = p10[7] + p10[8] + p10[9]
ball   = p10[4] + p10[5] + p10[6]
```

不能把四类编号直接当成原模型十类编号；尤其原十类 4–6 是滚动体、7–9 是外圈。

完整结果：[contact_metrics.csv](contact_metrics.csv)。每种配置目录有文件与窗口逐项十类/四类概率、真值、预测、混淆矩阵、权重 SHA256 和特征 NPZ。

独立 FCN 与新训练最终适配器对四类数据均塌缩为外圈预测；外部参考的改动没有解决这个问题。官方模型同样没有可用四类表现。不能据此区分到底是外壳传递路径、带宽缺失、工况参考不匹配还是其他域差异造成；这些是待分别干预的机制假设，不是已经证明的失败归因。

## 合理的最小修改

主链保留 `retrained_fcn` 的冻结 encoder 与 128 维隐藏表示，用当前训练录制的四类标注拟合一个新的线性头。标准化和分类器只能访问当前划分的训练录制；整个测试文件留出，固定超参数，不使用目标测试分数来决定轴、参考、特征或训练轮数。原参考/三轴的汇聚规则保持一致。

这项修改检验“预训练表示是否仍有用”，与“原十类头无需适配就能诊断”是两个不同命题。若新头有效，雷达学生应学习经适配的教师表示和四类分布；不能把原模型全部判外圈的输出当作可靠教师标签。当前每类只有两条录制，无法同时支撑新的训练、调参验证和独立最终测试；所有二选一录制划分均应完整报告，后续新增独立录制作为真正锁定模型后的测试。

上游仍要保留监督雷达基线、无教师基线、教师配对打乱对照，避免把普通四类监督的效果误归因给跨模态知识迁移。

## 供后续训练读取的文件

主接口为 [retrained_fcn_fixed_external/contact_features.npz](retrained_fcn_fixed_external/contact_features.npz)：

| key | 形状 | 说明 |
|---|---|---|
| hidden_mean | 88 × 128 | 外部参考及 XYZ 汇聚后的主表示 |
| hidden_axes | 88 × 3 × 128 | 保留各轴表示，参考已汇聚 |
| feature_map_mean | 88 × 128 × 47 | 空间特征图，供进一步算法使用 |
| probs10_mean / probs4_mean | 88 × 10 / 88 × 4 | 先对单次预测 softmax，再汇聚；不是平均 logits 的 softmax |
| logits10_axes / logits10_mean | 88 × 3 × 10 / 88 × 10 | 对应平均 logits，含义与平均概率分开 |
| labels / states | 88 | 四类 0–3；keep/bigNormal 保持 -1，以 states 区分 |
| file_names / window_rows / baud / bag_id | 88 | 与 [metadata.csv](retrained_fcn_fixed_external/metadata.csv) 同序 |

读取训练集合必须先做 `labels >= 0`。`bag_id` 表示录制对应关系，不代表样本逐窗时间对齐。keep/bigNormal 只能用于额外测试；bigNormal 的外部正常真值可在**计分阶段**映射为 0，不能把该文件加入训练或选参。

复现：

```bash
conda run --no-capture-output -n m2vllm python \
  /home/huangyating/anomaly_detection/four_class_chain_20260922/contact/evaluate_contact.py
```

后续真实 LLM 接口由 `run_llm_bridge.py` 实现：四类概率按故障部位分配到原十类，再经过当前最终适配器的 `linear3` 生成 5 个信号 token，送入冻结 Qwen+LoRA。三档严重度仅均匀分配，以避免虚构已知严重度；该方案是新增的四类语义接口，LLM 的输出必须与分类准确率、对输入概率的忠实度分别计分。

已实际完成 16 条接口控制：四类 oracle 一热概率 4 条，生成分类准确率及对概率 argmax 的忠实度均为 100%；原 FCN 的 12 个文件概率 12 条，生成对概率 argmax 的忠实度为 100%，其中主四类 8 文件诊断准确率仍为 25%、macro-F1 10%。全部无解析失败或生成截断。结果见 [LLM 接口控制](llm_bridge_controls/generation_metrics.csv)，这证明该接口可执行，同时直观显示语言模型不会自动修复错误诊断分布。
