# 从原始 bin 统一重选目标距离门

脚本 `reprocess_geometry.py` 为本批 12 份雷达录制准备，默认目标距离 **0.45 m**，所有类别统一使用 **0.29–0.61 m** 搜索区间。接收配置仍为归档的 R0；不连接雷达、不下发配置、不训练模型。

用户确认所有测量距离均在四十多厘米。历史外圈和 keep 导出选择了约 0.884 m，现有 NPZ 只保留这一区域附近三个 bin，因此必须取得原始 ADC bin 才能修正。单纯修改导出中的距离标签不能恢复信号。

## 先清点，再运行

把本批 **12 个原始 bin** 放到同一目录（允许子目录，文件名保留原样）。只需上传雷达 bin，接触式继续使用现有 NPZ/JSON，不需要重新上传 DAT。

先执行只读清点，将下面 `/path/to/original_bins` 换成真实路径：

```bash
/home/huangyating/miniconda3/bin/conda run --no-capture-output -n m2vllm \
  python /home/huangyating/anomaly_detection/four_class_chain_20260922/scripts/reprocess_geometry.py \
  --raw-dir /path/to/original_bins \
  --output /home/huangyating/anomaly_detection/four_class_chain_20260922/geometry_corrected_v1 \
  --distance-m 0.45 \
  --config /home/huangyating/anomaly_detection/four_class_preprocessing_20260921/雷达原始配置.cfg \
  --check-only
```

只有清点通过，再移除 `--check-only` 执行同一命令。默认使用 CPU 两线程、当前 Python 环境；运行后保留全套旧结果，新结果只写入 `--output`，该目录必须不存在或为空。

## 实际步骤与输出

1. 清点已知 12 个 bin：缺失、重名、大小与历史清单不符会列出并停止；`--check-only` 不创建输出目录，仅检查清点和配置，尚不读取全部数据计算 SHA256。
2. 正式运行先对所有原始 bin 计算 SHA256，与历史原始清单逐一比对。任一不匹配立即停止，不能用其他录制冒充缺失文件。
3. 校验现有接触式 NPZ 的历史哈希，逐字节复制 NPZ 和 JSON；保留四类之外的 keep、bigNormal。
4. 调用原 `preprocess.py` 的 `radar_export()`，对全部 12 份雷达使用同一物理 ROI。原始 bin 和原始导出均只读。
5. 合并 `results/summary.json`，原样保留 `recording_bags.json`，保存实际输入及历史清单哈希；调用原 `verify_exports.py` 检查导出。
6. 调用支持 `--source/--output` 的特征提取程序，生成新 `radar/features.npz`、`metadata.csv`、质量审计、固定基线和彩图。

新目录主要内容：

```text
geometry_corrected_v1/
  results/       # 12份重新导出的雷达 + 12份原样复制的接触式 NPZ/JSON
  radar/         # 新特征、映射、质量表、固定探索基线、彩图
  provenance/    # 历史清单与校验、使用的配置/代码快照
  inventory.json
  status.json
```

`--existing-results` 可以指定另一份完整的本批导出；默认是 `four_class_preprocessing_20260921/results`。必须仍含本批 12+12 录制、原始清单、校验和 bag 关联。

该脚本保留“同时采集但没有逐窗时间对应”的事实，**不会自动建立同步窗口配对**。统一 ROI 也不等于已经排除多径、饱和、转速和安装差异。完成后先检查新距离峰和谱图，再训练学生；这里不会自动改动本次训练协议或已有模型。
