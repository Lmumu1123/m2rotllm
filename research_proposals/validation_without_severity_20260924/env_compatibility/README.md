# 环境特征是否能直接输入当前冻结雷达 encoder

2026-09-24。**本次停止在兼容性检查，没有运行或报告环境分类准确率／误报率。** 旧 `iq_frame_shape` 与现行 `frame_shape` 的频带边界一致，但频带内功率的计算不同；不能只因同为 128 维就当作完全一致的输入。

## 已核对的相同和不同

| 步骤 | 9/18 环境归档 | 当前 v2 | 判断 |
|---|---|---|---|
| IQ / 快时间 FFT | 2I/2Q、4 RX、256 点、去均值、Hann、补到 512 | 相同基本解码与 FFT | 一致 |
| ROI | 文件名距离 ±16 cm，前 3 帧选峰，左右相邻各一格 | 用户距离 45 cm ±16 cm，同样选峰 | 同一物理规则，不应强迫不同距离都用 45 cm |
| 输入窗口 | 每 20 帧，2 秒，不重叠 | 同样 | 一致 |
| 单元尺度与 DC | 所有 chirp 的幅值中位数；全帧均值 | 仅有效 chirp 的中位数；有效 chirp 的帧均值 | 有缺失时不同；环境归档 652 窗均为完整计划内 chirp，故本批不触发此差异 |
| 功率汇聚 | 对完整帧 Hann 后 FFT，双边功率相加，帧均值，再 12 单元中位数 | 同样 | 顺序一致 |
| **慢时间 FFT 长度** | **2048，约 0.9765625 Hz 网格** | **4000，0.5 Hz 网格** | **不同** |
| 128 个频带 | `[5,6),[6,8),...,[780,800)` | 相同 | 边界逐值相同，但频带内采样点不同 |
| 幅度尺度 | 无帧功率密度归一化 | 除以 `2000 × sum(Hann²)` | 理想无截断 log 中心化可消去统一尺度，不能消去网格采样差异 |
| log 数值处理 | `log10(band_power+1e-14)` 后中心化 | 保存 float32 逐频 log，再还原功率；频带均值；下限截断后 log 中心化 | 数值处理也不完全相同 |

对相同的合成 IQ 分别执行两套帧功率处理，128 维输出确实不同。例如 33 Hz 复正弦的最大单维差约 0.437。这只是**合成算子差异检查**，不是用户数据的环境性能或误差幅度估计。宽带随机输入的差异较小，也不能由它保证所有故障输入都不受影响。

旧环境 `features.npz` 只保留了帧功率的 128 个带均值，没有保存逐帧 IQ 或完整逐频帧功率。里面的 `spectra[652,1591]` 是另一条跨帧拟合分支，不能冒充 `frame_shape` 所需的逐帧功率谱。

## 最少怎样修复

1. **要严格测试现有冻结模型**：找回 9/18 原始 bin，或者其保留完整有效掩码的 ROI 复 IQ，使用现行同一 `nfft=4000`、功率与 log 规范重新提取。继续按文件名物理距离选 ROI，不按预测好坏选峰。然后直接加载现有训练集 StandardScaler 与权重，分别报告 36 个旋转正常文件的误报；off 单列。此路径无需重训 encoder。
2. **暂时无法找回原始环境数据**：可另立兼容旧 2048 规范的开发对照，将已有四类 ROI IQ 重提取到旧规范并重新训练相同方法，再测试环境归档。这样比较的是“统一到旧前端后重训的系统”，不是“现有 encoder 无修改泛化”。本次没有执行这一替代实验。
3. 不建议把旧的 128 维带功率插值成新的 128 维带功率并称为精确修复：频带内信息已被平均丢失，且中位数等操作不能任意交换。也不应在待测环境重新拟合 StandardScaler 来掩盖输入差异。

即使完成统一，normal-only 压力测试也只回答正常误报，不能回答故障召回或丰富故障知识。这 42 个文件此前已经参与环境前端开发，所以测试应明确称为既有环境数据的压力检查。文件后缀 normal1/2/3 的物理独立性仍未确认；已有哈希只排除了逐字节重复，未证明独立启动／重新安装。
