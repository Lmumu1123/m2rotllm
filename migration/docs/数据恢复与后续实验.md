## 三个恢复层次

| 想做什么 | 最少需要什么 |
|---|---|
| 阅读结果、重算指标、检查保存学生 | 仓库中的预测/特征/模型及 Python 环境；不需要重新上传全部 ADC |
| 从当前 ROI 重提特征、重新做教师推理和训练 | 上述项目加新批 `upload/`；若跑宽 ROI 几何分支还需 `wide_cache_local/`；接触教师权重及正常参考不能缺 |
| 修正距离选区、改变 ADC 解析/快时间处理 | 原始 BIN、采集 cfg、清单和日志；ROI、功率图或 embedding 均不能还原被丢弃的距离相位 |

能重载历史学生不等于能重建教师，也不等于能重跑源数据回归。原公开数据精度保持验收需要相应数据或可核验的同协议特征缓存与划分；不能只凭旧 CSV 对新模型重新认证。

## 优先直接复制现成导出

在旧服务器上运行下面的复制示例，将 `newhost` 和目的目录改成实际值。这是数据传输示例，不会由迁移打包自动执行：

```bash
rsync -a --info=progress2 /media/nas_users/huangyating/data/upload/ \
  user@newhost:/path/to/c2r_data/upload/
rsync -a --info=progress2 /media/nas_users/huangyating/data/wide_cache_local/ \
  user@newhost:/path/to/c2r_data/wide_cache_local/
```

在新主机设置 `C2R_DATA_ROOT=/path/to/c2r_data`，使其下面直接存在 `upload/` 与 `wide_cache_local/`；模型资产路径按仓库迁移入口配置。再核对迁移清单和 DONE 中的校验和。

**有原始完整导出目录及 `export_catalog.json` 时**，可在工具目录执行：

```bash
python anomaly_detection/local_preprocessing_r2_20260928/preprocess_local.py verify \
  --output /path/to/c2r_data
```

若只复制了服务器现有的两个子目录，不能用伪造的原始 catalog 冒充整批导出校验；先从 Mac 补齐顶层文件，或者明确使用本轮派生审计清单核对现存文件。服务器曾核对 468 个上传文件及 12 个 DAT 压缩副本的 SHA256；派生清单来源见 `r2_validation_20260928/audit/`。旧审计通过不代替新机器传输后的校验。

## 如果没有复制 HDF5，就在 Mac 从原始数据重新处理

工具包在 [local_preprocessing_r2_20260928](../../anomaly_detection/local_preprocessing_r2_20260928/README_本地预处理.md)，只需 NumPy、h5py，无需 GPU。以下在该工具目录运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -p 'test_*.py' -v

python build_manifest.py \
  --data-root "/Users/anthea/Desktop/C2RLLM/data大量测试" \
  --output manifest.csv
```

核对生成的 manifest、review 和 summary：应为 144 段雷达、12 条接触长会话、36 个条件各四段。优先使用当时已核验的 Mac 原 manifest，并保留人工修正记录。已知 `20260927-194219-in-1000r-20m.bin` 的 `20m` 是用户确认的笔误，实际为 20cm；自动解析可能将其列为待处理，必须在清单里更正距离并确保该文件计入 144 条，不能因此丢掉此录制。原始文件无需改名。不要单凭文件名时间猜测逐窗配对。

用新的输出目录，按本批确认的 R2 配置导出：

```bash
python preprocess_local.py process \
  --data-root "/Users/anthea/Desktop/C2RLLM/data大量测试" \
  --manifest manifest.csv \
  --cfg R2_reference.cfg \
  --radar-format headerless_reordered_adc \
  --output "/Users/anthea/Desktop/C2RLLM/R2_export_migration"

python make_qc_report.py \
  --output "/Users/anthea/Desktop/C2RLLM/R2_export_migration"
python preprocess_local.py verify \
  --output "/Users/anthea/Desktop/C2RLLM/R2_export_migration"
```

该 `radar-format` 只适用于已去网络包头、重排好的 ADC 字节流，不是任意 DCA 网络抓包解析器。R2 为 256 ADC 点、4RX、单 TX、192 chirp/帧、40ms 帧周期、120+80μs chirp 周期；帧内 5kHz，平均每秒 4800 个实际观测，有 4% 名义空槽。不能将其跨帧接成均匀 4800Hz 或无缺口的 5000Hz 波形。

正式导出需要保留和迁移：`upload/`、`wide_cache_local/`、catalog、manifest、summary、QC、verification、来源 SHA、实际使用 cfg 和工具版本。若只为了现有主链重跑，可先传紧凑 `upload/`，但宽 ROI 几何检查会缺输入。不要仅上传频谱图或 128 维 embedding；它们不能供后续更改前端。

接触式仍是 4000Hz、2g 量程。完整 `[4096,3]` 包保留原值，模型输入取中间 `[48:4048]`。不跨包拼接，不用插值把断包补成真实观测；内圈截顶也不能由滤波恢复。

## 下一步实验按什么顺序继续

1. **先修采集质量的小样。** 提高接触量程试录，检查内圈高转速是否仍截顶；核对串口完整包、单位和 XYZ 安装方向。量程档位以设备支持为准，不能从已被截断的峰值推算真实最大振幅。
2. **补全雷达几何输入。** 做上述 20cm 宽复数重导出、确认测距基准；固定与类别无关的选区规则，在现有批次继续开发，不冒充新盲测。
3. **先让接触教师跨转速可靠。** 保留绝对频率与阶次/包络的匹配对照，重点检查滚动体；任何接触头/骨干适配都要重新做公开源回归，最多下降 0.5 个百分点。新头通过接触本地测试不等于通过源保持。
4. **再训练并检验跨模态知识。** 保留只学类别、真会话特征、类原型、人为类别向量、同类错转速和完整损失六种对照。除分类外，还比较特征误差和固定接触读取器；所有六个物理目标一起报告，不能只挑更好项。
5. **固定方案后再采独立留出。** 按新完整会话/采集日期留出，记录轴承实体、安装、转速、距离、量程、cfg、串口日志；同一条 DAT 再切片不算新独立测试。新 R2 批次已经用于多轮开发，后续最终验收要有未见批次。

每次运行应创建新输出目录，同时保存协议、输入哈希、模型版本、种子、scaler、标签映射、训练/测试 ID 与逐条预测。历史脚本中不少入口会拒绝覆盖归档目录；迁移后继续实验要用新的运行目录或脚本提供的输出参数，不为省事删除归档让它重跑。
